# Zhiyin 设计原则

## 1. 事实先于理论

任何理论解释都必须能够回到具体经历、资料来源或可重复的观察。

模型生成的流畅文本不是理论证据。

## 2. 不依赖模型本身“知道”理论

在理论进入正式系统前，至少经过：

```text
资料收集
  ↓
来源登记
  ↓
结构化学习
  ↓
概念边界整理
  ↓
案例对照
  ↓
反例和误判检查
  ↓
版本化发布
```

没有经过这条链路的内容，只能作为：

- 对话中的临时措辞；
- 待研究问题；
- 未验证假设；
- 外部资料检索结果。

不能作为 Zhiyin 的理论依据。

## 3. 用户是经验主体

用户的真实经历拥有最高优先级。系统的任务不是把人塞进某个理论，而是帮助用户观察、理解和形成自己的解释。

## 4. 不做预设分类器

不预先把用户分配给某种流派、类型或人格标签。

记忆 Agent 和探索发现 Agent 可以在长期互动中逐步发现：

- 反复出现的处境；
- 情绪和身体感受；
- 想法、判断和期待；
- 关系互动模式；
- 资源和行动能力。

这些是系统内隐整理的工作记忆，不是对用户的最终定义。

## 5. 多 Agent 不是多套人格

多个 Agent 的意义在于：

- 分离职责；
- 节约上下文；
- 降低单一模块的偏见；
- 让不同类型的问题拥有不同工具；
- 方便来源和过程追踪。

不是为了制造更多“声音”，也不是为了提前写出一套封闭理论。

## 6. 每次回答都要可解释

回答至少应能说明：

- 我听到了什么；
- 哪些是事实；
- 哪些只是当前候选模式；
- 下一步要验证什么；
- 哪个 Agent 参与了本轮工作；
- 哪些内容来自外部资料。

## 7. 保持开放和可审计

社区贡献的理论、Agent 和案例都应尽量保留：

- 来源；
- 版本；
- 作者或贡献者；
- 适用边界；
- 反例；
- 测试记录；
- 废弃或修订原因。

## 8. 少约束发挥，保留必要边界

给 Agent 足够大的理解空间，不把每句话都压缩成固定心理学术语。

但仍然需要保留：

- 风险识别；
- 事实与推断区分；
- 记忆授权；
- 隐私保护；
- 来源追踪；
- 现实求助边界。

目标不是给模型加更多人格，而是让它更可靠地理解一个具体的人。
