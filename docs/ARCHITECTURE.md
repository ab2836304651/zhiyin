# Zhiyin 架构说明

## 1. 总体链路

```text
用户输入
  ↓
交互层
  ↓
总控 Agent
  ├─ 风险筛查
  ├─ 当前意图识别
  ├─ 会话状态读取
  └─ Agent 路由
       ↓
  最小上下文包
       ├─ 记忆 Agent
       ├─ 线索 Agent
       ├─ 用户选择的工作视角 Agent
       ├─ 知识/工具 Agent（可选）
       └─ 输出审查 Agent
       ↓
  统一汇总
       ↓
  自然语言回复
```

用户只看到一段连续对话，不需要理解 Agent 数量和底层编排。

## 2. 上下文包

总控 Agent 不把完整会话直接复制给每个模块，而是为每轮生成小型上下文包。

### 风险筛查包

```json
{
  "current_input": "用户当前输入",
  "session_state": "当前话题和阶段",
  "risk_signals": ["需要进一步确认的信号"],
  "required_action": "普通回应 / 安全确认 / 现实求助"
}
```

### 记忆检索包

```json
{
  "query": "当前问题真正需要的历史信息",
  "authorized_memories": ["与当前问题直接相关的记忆"],
  "excluded_memories": ["敏感、无关或未授权内容"]
}
```

### 线索更新包

```json
{
  "facts": ["用户明确表达的事实"],
  "experiences": ["用户描述的主观体验"],
  "hypotheses": ["暂时解释"],
  "questions_to_verify": ["下一步需要确认的问题"]
}
```

### 视角 Agent 包

```json
{
  "selected_view": "用户选择的主 Agent",
  "view_description": "该视角观察什么",
  "view_limits": ["该视角不负责什么"],
  "source_status": "该视角的理论依据是否已经过学习与验证"
}
```

## 3. Agent 协作纪律

### 单一建议源

同一轮多个 Agent 的意见先进入总控汇总，不让多个 Agent 互相覆盖或同时向用户发答案。

### 事实和推断分层

每条分析至少标记为：

```text
事实
体验
工作假设
待验证问题
```

### 不把模型输出直接升级成理论

模型可以：

- 总结已有资料；
- 对比不同概念；
- 解释可能的理解；
- 生成待验证问题；
- 提醒用户某个结论的依据不足。

模型不能仅凭自己的生成结果宣称：

- 这是某一流派的完整理论；
- 这是经过验证的心理学结论；
- 这适用于所有人；
- 这能够解释用户的行为。

## 4. 主 Agent 与工作视角

用户选择一个主 Agent，代表本轮优先采用哪一种观察方式，而不是选择一个封闭真理。

主 Agent 应当是可插拔的：

```text
主 Agent
  ↓
工作视角 / 观察问题
  ↓
证据与体验
  ↓
工作假设
  ↓
验证问题或小行动
```

未来的 Agent 贡献应包含：

- 角色说明；
- 观察范围；
- 不适用范围；
- 理论来源；
- 典型误判；
- 评测案例；
- 版本记录。

## 5. 记忆策略

- 用户明确授权后才写入长期记忆；
- 推断默认不进入长期记忆；
- 记忆必须带来源、时间和敏感度；
- 用户可以查看、修改和删除；
- 相关性优先于数量，避免把整段历史塞回模型；
- 多 Agent 共享的是必要摘要，不是完整私密原文。

## 6. 风险与边界

风险筛查优先于普通分析。

当出现即时安全风险时，系统应当：

1. 停止普通理论探索；
2. 确认用户当下是否安全；
3. 鼓励联系现实中的支持者和专业资源；
4. 明确说明 AI 不是人工危机干预。

开源版本不提供医疗诊断和治疗处方功能。
