# Zhiyin

> 一个轻装、可随时使用的多 Agent 心理探索实验室。

Zhiyin 不是一个把用户套进既有心理学体系的诊断工具，也不是一个由理论按钮驱动的聊天机器人。

它更像一个持续在场的工作环境：

- 先听见用户正在经历什么；
- 帮用户保存真正重要的经历；
- 从多次对话中自动发现现象、想法、情绪、关系和资源；
- 必要时再调用有来源的外部资料或工具；
- 把用户当作自己经验的专家，而不是等待被理论解释的对象。

## 当前设计理念

### 1. 不预设心理学体系

我们暂时不构建“现象学、认知、叙事、系统、依恋”等流派选择器，也不提前把用户归入某一种理论。

这样做是为了避免：

- 过早给用户贴标签；
- 让理论框架遮蔽用户的真实处境；
- 用预设分类替代对具体经验的理解；
- 把模型原生能力压缩成几个固定选项。

未来如果需要，可以由用户、开发者或官方提供经过整理的权威资料，作为可引用的外部视角，而不是强行成为系统底色。

### 2. 现象和模式由 Agent 自动发现

“现象”“认知”“叙事”“资源”等概念不需要用户先学习，也不应该成为用户进入系统的门槛。

记忆 Agent 和探索发现 Agent 可以在用户的长期互动中逐步整理：

- 用户反复提到的处境；
- 情绪和身体感受的变化；
- 想法、判断和期待；
- 关系中的互动模式；
- 用户已经做到的事和可利用资源；
- 尚未理解、需要继续观察的矛盾。

这些内容是系统的内隐工作记忆，不是对用户的最终解释。

### 3. 用户是自己经验的专家

Agent 可以帮助整理、追问、连接和发现，但不应该抢走用户的解释权。

系统的基本姿态是：

```text
用户的经历是事实源头
用户的感受是第一手材料
Agent 提供观察和整理
用户决定什么对自己有意义
```

### 4. 少给 Agent 套枷锁

多 Agent 不是为了制造更多人格，而是为了：

- 把职责拆小；
- 让每个模块保留更大的发挥空间；
- 只传递必要上下文；
- 避免一个大模型被大量无关理论占满；
- 让来源、推断和输出能够分别追踪。

本项目不追求“看起来很专业”的固定话术，而追求：

- 不乱下结论；
- 不把猜测说成事实；
- 不把用户经历压扁成标签；
- 不因为模型说得流畅就相信它。

## 当前多 Agent 架构

```text
用户输入
  ↓
倾听与总控 Agent
  ├─ 接住原话和当下处境
  ├─ 判断本轮需要什么帮助
  └─ 管理对话连续性
       ↓
按需调用
  ├─ 记忆 Agent
  ├─ 探索发现 Agent
  ├─ 关联推理 Agent
  ├─ 资料/工具 Agent（可选）
  └─ 边界审查 Agent
       ↓
自然回复
```

### Agent 职责

| Agent | 主要职责 | 原则 |
| --- | --- | --- |
| 倾听与总控 | 承接现场、维持对话、决定是否调用其他 Agent | 不抢先替用户下结论 |
| 记忆 Agent | 整理用户主动授权的重要信息和长期线索 | 记忆是理解线索，不是判决 |
| 探索发现 Agent | 从经历中发现情绪、想法、模式、关系和资源 | 不要求用户先掌握理论词汇 |
| 关联推理 Agent | 跨时间寻找重复模式、变化和可能联系 | 保留多种解释，不强行收敛 |
| 资料/工具 Agent | 在需要时调用有来源的资料、搜索和工具 | 外部信息不直接变成用户事实 |
| 边界审查 Agent | 检查事实、风险、隐私、授权和表达边界 | 少限制模型发挥，但不放弃必要边界 |

## 事实与理论纪律

系统内部尽量区分：

```text
事实：用户明确说过，或有可追踪来源
体验：用户主观感受到什么
模式：多次经历中可能出现的重复线索
工作假设：暂时解释，仍需要验证
外部资料：有明确来源、但不自动等于用户事实
理论引用：经过资料学习、来源追踪和案例验证的内容
```

核心原则：

> 模型可以整理、比较、追问和提出假设，但不能因为语言流畅，就把生成内容当作理论依据。

未经学习、蒸馏、来源追踪和验证的模型输出，只能作为：

- 临时措辞；
- 待研究问题；
- 工作假设；
- 外部检索结果。

不能直接进入正式理论库。

## 当前原型能力

- 手机、平板、电脑响应式界面；
- 对话空间和本地模拟回复；
- 多 Agent 路由链路展示；
- 风险表达的安全提示演示；
- 用户主动保存的记忆原型；
- 线索、事件和待验证问题展示；
- 成长目标和小行动原型；
- 轻量架构总览；
- 本地 `localStorage` 演示数据；
- 消息自动保存，后台探索 Agent 在不打扰用户的情况下持续复盘并更新候选线索；
- 对话界面默认只呈现交流内容，不展示记忆、发现、关联和审查 Agent 的内部轨迹；
- 响应式移动端菜单和视图切换。

当前版本是**架构和交互评审原型**，没有接入真实大模型、真实用户账户或生产级数据库。

## 本地运行

需要 Python 3：

```bash
python -m http.server 4173
```

打开：

```text
http://127.0.0.1:4173
```

也可以使用：

```bash
npm start
```

## 开源边界

- 这不是医疗器械、诊断工具或心理治疗系统；
- 不进行精神疾病诊断、治疗处方或危机风险诊断；
- 不把用户当作被动接受理论的对象；
- 不把模型生成的理论包装成既有理论；
- 任何正式知识模块都需要保留来源、版本、验证记录和不确定性；
- 高风险内容只做安全提示和现实求助引导，不把 AI 伪装成人工危机干预。

## Git

本项目以开源仓库形式维护。提交前请确认：

- 不包含真实用户信息；
- 不包含 API Token、密钥或环境变量；
- 不把任何真实心理案例直接公开；
- 涉及理论、案例和知识库时，记录来源和处理过程。
